# Демо ИИ-консультанта ekt.kz

`index.html` — исходник опубликованной страницы с чатом и видимым каталогом из БД. Серверной логики и секретов в HTML нет.

## Запуск и настройка

Откройте файл через обычный статический HTTP-сервер. При переносе измените константы `ENDPOINT` (чат) и `CATALOG_ENDPOINT` (публичный GET каталога) в HTML и настройте CORS на n8n. Workflow экспортированы в `n8n/workflows/ekt_assistant.json` и `n8n/workflows/ekt_catalog_view.json` в корне репозитория; им требуется существующий Postgres credential, а агенту — OpenAI credential.

Витрина: фотографии, поиск по имени/артикулу/категории, категории и фильтр наличия. Числа, цены и остатки не зашиты в HTML. Пустой каталог, отсутствие совпадений и ошибка загрузки различаются; после ошибки есть повторная загрузка. Кнопка «Спросить об этом товаре» отправляет вопрос в текущий чат и не добавляет товар в корзину.

Фото в карточках и Markdown-ответах принимаются только из `https://ekt.kz/upload/`, без query/hash, userinfo и обхода пути. Используются lazy loading, no-referrer, alt и fallback. Рендеринг через DOM/textContent без raw HTML. Ссылки на карточки ограничены `https://ekt.kz/catalog/`.

## Локальные тесты

Из корня репозитория: `node site/demo/tests.cjs`. Зависимости не нужны: проверяются безопасные изображения, XSS/URL, JSON/NDJSON, числовая валидация каталога, фильтры и карточки. Визуальная desktop/mobile QA — в корневом `TEST_REPORT.md`.

Это отдельное публичное демо на временном адресе, не установленный скрипт на ekt.kz. Демо-корзина не оформляет заказ на сайте партнёра.
